# Phase 15 design — deterministic BOQ and cost V2

The verified baseline is `ca0cbc2` / `backend-v1-phase14-complete`; the tree and tag diff were clean before work. V1 estimates and Phases 9–14 calculation behavior stay frozen. The Supabase 500 investigation has one independent agent and its own evidence report.

1. **Rate books:** strict, source-controlled synthetic definitions, selected by ID. Each report embeds a normalized full snapshot and SHA-256 canonical content hash. No external rates or admin CRUD. Versioned changes create new artifacts.
2. **Currency:** INR, USD and EUR only, each deliberately constrained to two minor digits in v1. Entry currency inherits the book; cross-currency mixing and FX are unsupported.
3. **Region:** explicit country, optional region/city/code in the selected book. No inference from project or account.
4. **Rate identity:** unique machine entry code plus exact material/mode/unit/bag-mass and optional assembly/specification qualifiers. Multiple matches fail; no precedence or fuzzy matching. Physical and purchase entries matching the same requirement are ambiguous, not additive.
5. **Materials:** one canonical BOQ line per authoritative material requirement. Physical mass/volume/liquid pricing uses Phase 14 final exact rational; bag/piece/each purchase pricing uses the explicit upstream purchase count. Piece/each quantities require purchase mode. Bag mass must match exactly. No package conversion is invented.
6. **Labor:** explicit direct unit or productivity/hour rules. Each rule targets an assembly and layer, with one rule per assembly/layer to prevent overlapping labor. Consume unique Phase 14 items once, converting their existing mm²/mm³ bases to m²/m³ exactly. No geometry or productivity assumptions. Unmatched items remain NOT_EVALUATED labor lines.
7. **BOQ:** MATERIAL, LABOR, ADJUSTMENT categories. IDs derive from canonical source identity; groups reference canonical line IDs by category, material, level, assembly, specification and trade, never duplicate priced lines.
8. **Subtotals:** sum emitted rounded material and labor amounts in integer minor units; direct subtotal is their sum. No hidden fractions.
9. **Overhead:** optional explicit percentage or fixed adjustment with category OVERHEAD and declared basis.
10. **Contingency:** the same bounded adjustment model, category CONTINGENCY. No default allowance.
11. **Charges:** explicit CHARGE or ADJUSTMENT rules, percentage/fixed additions or fixed deductions, unique order and code; basis MATERIAL, LABOR, DIRECT or RUNNING. RUNNING includes previous rounded adjustments. Deductions cannot make running cost negative. No statutory tax claims.
12. **Rounding:** upstream rationals stay exact; rates/productivity accept six decimal places. Rational intermediate multiplication; half-up once per monetary line to two decimals. Subtotals sum rounded lines; adjustments round once on their declared rounded basis; final sum is exact minor units. Display quantity precision is independent. Evidence preserves exact numerator/denominator.
13. **Provenance:** line → material/calculation item → takeoff item → architectural entities. Report includes construction engine, recipe pack, normalized book/policy/options, hashes, warnings and upstream coverage. FULLY_PRICED refers to represented supported scope only. Excluded equipment, transport, structure and MEP remain explicit; completeProjectTotal is never implied. Upstream partial coverage prevents completeTotalAvailable.
14. **Persistence:** additive migration 0009; immutable owner-private table, composite source FKs, RLS and signed RPC using the existing commit key and receipts. Database independently verifies ancestor identity, snapshot/report hashes, input fingerprint and report metadata. Input identity excludes output hash. Lock order is receipt key then cost fingerprint; artifact and receipt share one transaction. List is summary-only keyset pagination. Creation loads the persisted calculation; clients only choose book, strict policy and options.
15. **Phase 16 boundary:** no exports, frontend, AI, solver changes, live pricing, structural engineering, reinforcement, foundations, MEP, jurisdiction-specific rules or deployment.

Bounds cover input/report bytes, entries, rules, lines, groups, warnings and matching work. Invalid source relationships, ambiguous pricing or impossible units fail explicitly. Missing rates retain quantities and null amounts. Partial totals are named pricedSubtotal/pricedGrandTotal. Tests exercise exact arithmetic, provenance, immutable storage, signatures/RLS, concurrent keyed/keyless convergence and failure rollback through both PostgreSQL and local Supabase.
